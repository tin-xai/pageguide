# PageGuide Eval Tool Memory

Important current defaults and plan notes:

- Use the current CSV in `data-guide` as the evaluation CSV. Prefer `Copy of GuideTaskData - guide_task.csv`; fall back to `guide_task-2.csv` or the newest CSV if needed.
- The most important task fields are `task`, `website_url`, and `ground truth steps`.
- `ground truth steps` may be written as semicolon-separated steps; the evaluator maps this to `reference_steps` for Phase 3 judging.
- Use the OpenRouter API key from `.env`. Supported key names include `OPENROUTER_API_KEY`, `OPEN_REUTER_API_KEY`, and `open-reuter-api-key`.
- For current test runs, select only the last two runnable rows in the current CSV by default. `Check All Tasks` must only check all boxes in the select-task panel; `Start Evaluation` is the only visible action that starts a run.
- Run Playwright HEADFUL by default (MV3 extensions are unreliable in headless Chrome). Opt into headless with `PAGEGUIDE_EVAL_HEADLESS=1`; if headless can't load the extension it still retries headful.
- Extension is MV3 (lazy service worker), so do NOT rely on catching the service worker. Resolve the extension ID deterministically from the load path (`expected_extension_ids` in runner.py: SHA-256 of abspath/realpath mapped to a-p), falling back from any live worker. Then open `chrome-extension://<id>/sidepanel/panel.html` and verify `chrome.storage.local` is available.
- Keep `guideEvalMode` scoped to evaluation runs: it disables high-risk, confirmation, and low-confidence pauses, but keeps the 15-step cap.
- CRITICAL: content scripts run in an ISOLATED world. The runner must NOT call `window.handleStepByStepGuide` / read `window._guidev2` via page.evaluate (main world) — those are invisible there and cause 15s timeouts with 0 steps. Drive the guide from the extension page via `chrome.tabs.sendMessage(tabId, {action:'handleQuery', query, forcedRoute:'guide'})` (after a `reset`), and poll progress from `chrome.storage.local` rewind keys (`RW_CURRENT`, `RW_IDX::<session>`), not from the page's main world. Find the task tab with `chrome.tabs.query` by host. Pref keys: `guideAutoMode`, `guideEvalMode`, `rewindCaptureEnabled`, `guideConfidenceFormula` (all in chrome.storage.local).
- Browser mode (default): **real Google Chrome** with the Chrome profile named **PageGuide** when it exists (`~/Library/Application Support/Google/Chrome`, profile dir e.g. `Profile 3`). Extension must be installed once in that profile via chrome://extensions → Developer mode → Load unpacked (this repo). Do NOT use `--load-extension` with branded Chrome (blocked → ERR_BLOCKED_BY_CLIENT). Override: `PAGEGUIDE_EVAL_BROWSER=chromium` for bundled Chromium + auto `--load-extension`. Profile name override: `PAGEGUIDE_EVAL_CHROME_PROFILE_NAME`. Quit Chrome completely before eval runs (profile lock).
- Browser profile (chromium mode only): `~/.pageguide-eval-chromium`. Sign in via `python -m eval_tool.login`. Override `PAGEGUIDE_EVAL_PROFILE` (`temp` = throwaway).
- Automatic credential sign-in: `eval_tool/accounts.txt` (gitignored; template `accounts.example.txt`) holds `name | login_url | username | password [ | user_sel | pass_sel | submit_sel ]` per line. `python -m eval_tool.auto_login` fills them into the persistent profile. `eval_tool/run_eval.sh` is the one-shot launcher (venv -> auto_login -> app); `SKIP_LOGIN=1` skips. Google often blocks scripted login; use `eval_tool.login` manually for it.
- Password-file fallback: if `accounts.txt` is absent, auto_login reads `password/password.txt` (free-form `Email/Username/Password` blocks, gitignored via `password/`) and combines it with the login-flow catalog in `eval_tool/credentials.py`. Buckets: `Google` header -> google creds, `Scratch` -> scratch, everything else -> default. Sites default to `quora,google,facebook,linkedin` (override `PAGEGUIDE_EVAL_SITES`); password path override `PAGEGUIDE_EVAL_PASSWORD_FILE`. Catalog selectors are best-effort.
- Do not edit the plan file when making implementation changes.
